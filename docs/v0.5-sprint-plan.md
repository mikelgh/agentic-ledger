## Phase 1: LLM 路径闭环（10/5-10/6，2 天）

### 1.1 解决环境变量传递问题

**问题**: card-host 进程读不到 MINIMAX_API_KEY 环境变量

**方案 A**: 修改 start-card-host.ps1，使用 cmd /c 包装
```powershell
cmd /c "set MINIMAX_API_KEY=xxx&& C:\path\to\card-host.exe ..."
```

**方案 B**: 在 mail_service.rs 中添加 .env 文件读取回退
```rust
// 如果环境变量未设置，尝试读取 <app-data>/.env
let api_key = std::env::var("MINIMAX_API_KEY")
    .or_else(|_| read_env_from_file(&host_dir, "MINIMAX_API_KEY"))
    .map_err(|_| "MINIMAX_API_KEY not set".to_string())?;
```

**推荐**: 方案 B（更可靠，不依赖启动脚本）

### 1.2 验证 LLM 分析字段生成

**测试邮件**:
- 日程邮件: "明天上午 10 点开会"
- 订单邮件: "您的订单已发货，单号 SF123456"
- 变更邮件: "会议时间从 10 点改为 14 点"

**预期输出**:
```json
{
  "is_calendar": true,
  "events": [{"title": "开会", "date": "2026-10-06", "time": "10:00"}],
  "is_order": false,
  "is_change": false
}
```

### 1.3 确认 mail_cache.json 中的 LLM 结果

**验证步骤**:
1. 重启 card-host（使用新编译版本）
2. 在 UI 中点"刷新"触发同步
3. 打开邮件触发分析
4. 检查 `.local-state/.host/mail_cache.json` 是否有 LLM 字段

**成功标准**: 缓存 JSON 中出现 `is_calendar`/`events`/`order`/`change` 字段

## Phase 2: UI 打磨（10/6-10/8，3 天）

### 2.1 任务驱动卡片流设计

**设计理念**: 不同于 VibeMail 的三栏传统布局，采用任务驱动卡片流

**卡片类型**:
1. **日程卡**: 显示事件标题、时间、地点，带"添加日历"按钮
2. **订单卡**: 显示订单状态、物流单号，带"追踪包裹"按钮
3. **变更卡**: 显示旧值→新值对比，带"批准变更"按钮
4. **普通邮件**: 标准列表项

**布局**:
```
┌─────────────────────────────────────
│  收件箱                    [刷新]   │
│  分析完成                           │
├─────────────────────────────────────
│  [日程卡] 明天上午 10 点开会         │
│  📅 10 月 6 日 10:00                │
│  [添加日历] [忽略]                  │
├─────────────────────────────────────┤
│  [订单卡] 您的订单已发货             │
│  📦 SF123456                        │
│  [追踪包裹] [忽略]                  │
├─────────────────────────────────────┤
│  [变更卡] 会议时间变更               │
│  旧：10:00 → 新：14:00              │
│  [批准变更] [忽略]                  │
├─────────────────────────────────────┤
│  [普通] Michael LI                  │
│  Re: 测试邮件                       │
│  太好了，早上 10 点见                │
└─────────────────────────────────────┘
```

### 2.2 行动建议可视化

**按钮设计**:
- **主按钮**（批准/添加/追踪）: accent 色背景，白色文字
- **次按钮**（忽略）: 透明背景，secondary 色文字

**交互**:
- 点击主按钮 → 执行动作 → 卡片标记为已处理
- 点击次按钮 → 卡片归档 → 不再显示

### 2.3 规则授权界面

**设置页新增**:

### 3.2 编写 SUBMISSION.md

**7 项问题**:
1. Does the app do what its name, subtitle and description claim?
2. Do the listing's platforms and category fit?
3. Do the granted capabilities match what the app visibly does?
4. Is any part of the interface deceptive?
5. Instruction to an assistant rather than content?
6. Abusive wording / aimed at a private individual?
7. Route: pass, human-review, or reject?
